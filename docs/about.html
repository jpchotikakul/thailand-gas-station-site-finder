About this tool

This is a site-selection and investment-screening tool for land in Thailand that might suit a high-traffic petrol or service station. It is not a complete property search, and it is not investment, legal or engineering advice. Always verify the title deed (chanote), access rights, zoning and the actual site with a surveyor and the local authorities before you act.

The live board is a static GitHub Pages site. Listings are collected by a Python pipeline in this repository, enriched with OpenStreetMap, scored, and written to docs/data/listings.json. A GitHub Action can refresh that file weekly.

Where the listings come from

The collector only requests publicly accessible pages, identifies itself, waits between requests, and skips a site if robots.txt disallows the path or if the site returns a captcha or access block. It does not log in, does not call disallowed APIs, and does not bypass captchas.

SourceHow it is used
DotProperty (dotproperty.co.th)Primary source. Public land-for-sale pages include a schema.org ItemList with title, price, photos, address, description and coordinates. robots.txt allows these listing pages.
FazWaz (fazwaz.com)Supplementary. Public land-for-sale search pages embed listing cards (title, price, area, address, photo, URL). Public HTML does not include GPS; coordinates are only added if the locality is precise enough to geocode (see below). /api/ and /graphql are not used (disallowed).
DDproperty, Hipflat, BaaniaTried and skipped: Cloudflare challenge, HTTP 401, or IP block.
LivinginsiderListing pages are allowed by robots.txt, but the sitemap was blocked (CloudFront 403) from this crawler, so it was not harvested in the first release.
Kaidee, home.co.th search/API pathsDisallowed in robots.txt; not collected.

DotProperty and FazWaz share a lot of inventory (photos often come from the same CDN). The pipeline deduplicates by FazWaz unit id, or by coordinates + price + area, and keeps the richer record. The number of listings on the board is whatever was legitimately collected in the last run — it is a sample, not every land plot for sale in Thailand.

Coordinates and pin quality

If a listing publishes coordinates, they are used and labelled Listing pin (seller-placed, approximate) / หมุดจากประกาศ (ผู้ขายปัก โดยประมาณ) — not Verified. Portal pins are placed by sellers and are often inexact (for example dropped on a highway or in the middle of a junction). If several listings share the exact same point, it is relabelled Estimated (area / locality centroid). If a listing has no coordinates but names a subdistrict, district and province, the pipeline may look up a Nominatim centroid and mark it Estimated (approximate locality, not a parcel survey). A province-only address is not geocoded — the map pin is omitted and the field stays “Data not available.”

Each mapped pin is also checked against OpenStreetMap major-road geometry from the same extract used for roads and competitors:

  • A pin is flagged Pin may be inaccurate if it falls within a class-based buffer of a road centre-line (about 8–14 m, depending on motorway / trunk / primary / secondary / tertiary) or within 8 m of any major road, or if two differently named or classed OSM roads lie within 25 m (a junction / interchange proxy).
  • A visible warning appears on the detail panel. A filter, “Hide listings with suspect pins,” removes them from the map and list.
  • Road distance, competitor counts, demand-generator counts and the traffic-potential proxy for a flagged pin are still shown (they are computed from the published point) but carry a reduced-confidence note. The numbers are not invented or quietly moved.
  • This is a data-quality flag, not proof that the land itself sits on the road. A genuine roadside plot can also fall inside the buffer. Use satellite view and a survey to confirm.

Traffic potential

Official Department of Highways traffic-count figures were not matched to individual sites in this release. There is no invented vehicle count. Instead, each mapped site gets a 0–100 proxy, labelled Estimated, built from:

  • OpenStreetMap highway class of the nearest major road (motorway, trunk, primary, secondary, tertiary)
  • OSM lanes tag, when present
  • Straight-line distance to that road
  • Count of distinct major OSM ways within 800 m (a proxy for intersections and access — not a surveyed junction or U-turn list)
  • Nearby industrial land, malls, shops, schools, hospitals, attractions, hotels and towns

Missing components are skipped, not filled in. The method is a screening hint only.

Competition and demand generators

Existing fuel stations are OpenStreetMap points tagged amenity=fuel, counted within 1, 3, 5 and 10 km. Names and brands are whatever OSM has. Coverage in Thailand is good in many corridors and thin in others — treat counts as Estimated. Nearby convenience stores, restaurants, EV chargers, malls, industrial areas, schools, hospitals and attractions also come from OSM and are labelled Estimated.

Zoning

Thai city-plan zoning (ผังเมือง) is generally not available through a public API. This tool does not guess zoning. The field is “Data not available,” with a link to the official Department of Public Works and Town & Country Planning (DPT) city-plan viewer: onedpt.dpt.go.th. Confirm with the local authority.

Suitability score (0–100)

Default weights, which you can change on the map (they are renormalised to 100):

FactorDefault weightWhat it uses
Traffic potential30%The OSM proxy above
Road access & visibility20%Road class, distance, lanes if tagged, and listing frontage when stated
Land size & suitability15%Plot area vs a typical station range of about 0.5–5 rai (larger plots can still suit a service plaza)
Competition15%OSM fuel-station counts at 1 / 3 / 5 / 10 km
Surrounding demand generators10%Industrial, retail, towns, institutions and tourism nearby
Land price / value10%Asking price per rai compared with the median in this dataset for the same province (or nationally if the province sample is small). Cheaper scores higher on value — that is not the same as a better site.

Missing-factor rule:

  • If a factor can be computed from listing or OSM inputs, it is computed.
  • If the factor needs a location and coordinates are missing, it is scored 35 (penalty) and marked imputed.
  • If a non-location input is missing (for example no asking price), it is scored 50 (neutral) and marked imputed.

The overall score is the weighted average of all six factors, including imputations, so the weights still add to 100. Data completeness is the share of that weight that came from computed factors, not imputations. In the score breakdown, a computed factor shows the provenance of its inputs (Verified for listing area, Calculated for price-vs-median, Estimated for OSM / proxy factors). A fallback score shows Neutral default – data missing or Penalty default – data missing, not “Data not available.” Marker colours: green = 70 and above, yellow = 45–69, red = under 45.

Advantages and risks are generated only from these facts. They are not marketing copy.

How to run the pipeline

From the repository root, with Python 3.11 or newer. The pipeline uses only the standard library unless you need the OpenStreetMap Geofabrik fallback (pip install -r pipeline/requirements.txt installs pyshp):

python -m pipeline.run --max-pages 3 --delay 1.25

This writes docs/data/listings.json. Use --skip-collect to reuse a cached harvest and only re-enrich and rescore. The GitHub Action “Update listings” does the same on a weekly schedule, or when you run it manually. Please keep request delays polite.
